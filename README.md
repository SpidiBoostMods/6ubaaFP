# spidiboost.6ubaaFP

Автор: **SpidiBoost**. Minecraft **1.21.4**, Fabric, Java 21, Fabric API.

Установка: `6ubaaFP-1.21.4-<версия>.jar` в `mods` нужного инстанса.

Автообновление проверяется при запуске клиента и подключении к серверу или локальному миру. Обновлятор отображает только установленные LittlePet, SpidiBan, 6ubaaFP и SpidiCard в одном окне; загружает подходящие релизы из SpidiBoostMods, сверяет SHA-256 и метаданные, сохраняет результаты и перезапускает игру один раз. JAR заменяются только после выхода игрового процесса. Резервные копии: `.spidiboost-updates/backups` текущего инстанса. Если надёжно воспроизвести запуск лаунчера нельзя, обновления устанавливаются после обычного выхода; запускать игру нужно через лаунчер.

GitHub недоступен — мод продолжает работать с установленной версией. Обновление одного мода не затрагивает конфигурации, миры или другие моды.

Релизы: https://github.com/SpidiBoostMods/6ubaaFP/releases/latest

Сборка: `./gradlew check build` (Java 21). Выпуск: тег `v<mod_version>`, автоматические проверки на Windows/macOS/Linux и публикация JAR, проекта с исходниками и manifest.

Версия **1.5.0**. Команды: `/6ubaafp start/full/stop/status/open/update`. Корень `/6ubaa` удалён.

Один запуск `start` или весь маршрут `full` отправляет `/hist` и `/dupeip` для каждого ника только один раз (без учёта регистра). Переход к следующей полной истории — через 5 мс после её ответа; `Лимит` не считается точным числом записей. Запоздалые записи сохраняют владельца. Пустой ответ не вызывает отдельной задержки; полностью отсутствующий ответ отмечается неполным после 6 секунд, без повторной отправки. Текущий игровой аккаунт исключается по живому профилю игрока, а не стартовой сессии лаунчера. Каждые 20 историй очищается только отображаемый чат; результаты и очередь остаются в памяти. Для красных аккаунтов с FP-банами добавляются присутствующие в TAB жёлтые твинк-аккаунты из той же группы: `nick (На сервере: twin1, twin2)`.
FP-проверка учитывает **все** жёлтые/золотые и красные/тёмно-красные никнеймы `/dupeip`, включая офлайн-аккаунты и отсутствующих в TAB. Проверки присутствия этих аккаунтов в TAB нет. Снимок TAB нужен только как исходный список владельцев для запросов `/dupeip`. Серые/другие цвета не проверяются. Результаты — `6ubaafp.txt` текущего инстанса.

Строка `nick was unbanned by Moderator.` исключает связанную с ней FP-запись. `ReallyWorld.` — автоматический разбан, такая FP-запись учитывается. Другой FP-бан этого же ника не отменяется: достаточно одной подходящей записи без ручного разбана. Автоматический разбан за читы не делает вручную снятый FP-бан подходящим. Запоздалый ручной разбан отзывает ранее найденное совпадение, пока запуск принимает ответы.

## Поиск предметов в инвентарях

```text
/6ubaafp inv none minecraft:compass, Алмазный меч
/6ubaafp inv full minecraft:compass, Алмазный меч
/6ubaafp invsee minecraft:compass
/6ubaafp inv full 1, 4, 2-5 compass,obsidian(6)
/6ubaafp inv пасхальный топор, minecraft:totem_of_undying, порыв ветра, obsidian(6)
/6ubaafp invsee full 32-34,56 compass(>=1),obsidian(<=64)
/6ubaafp stop
```

`none` (или без указания режима) — один текущий гриф. `full` — по очереди все грифы 1–56, с прежней навигацией через компас. `inv` и `invsee` равнозначны.

После `full` можно указать точный маршрут: номера, диапазоны и перечисления через запятую или пробел. Например, `1, 4, 2-5` даёт грифы 1–5 без повторов; `3` выбирает только гриф 3. Номера ограничены 1–56; маршрут всегда по возрастанию. Предметы отделяются от числового маршрута пробелом. Без маршрута сохраняется обход всех 56 грифов.

Каждому игроку из снимка TAB отправляется `/invsee nick`. Никнеймы из `/dupeip` в этом режиме не используются. Запросы строго последовательные; минимальный интервал — 5 мс, фактическая скорость зависит от ответа сервера и кадров клиента. Ушедшие из TAB и явно недоступные игроки пропускаются. Требуются серверные права на `/invsee`.

Через запятую перечисляются **обязательные условия (И)**: ID предмета (`minecraft:compass` или короткий `compass`) либо точное отображаемое название (в том числе заданное на наковальне). Пробелы около запятой необязательны. Регистр, цвета и повторные пробелы игнорируются; поиск по подстроке не применяется. Короткое имя известного vanilla ID имеет приоритет перед отображаемым названием; TAB предлагает полный `minecraft:id`. Название обычного непереименованного предмета зависит от языка клиента.

Количество суммируется по всем серверным слотам, а не по одному стеку. Суффикс `(6)` или `(=6)` требует ровно 6; `(>=6)`, `(>6)`, `(<=3)`, `(<3)` используют обычные математические сравнения. **Ноль всегда исключён**: `<2` — только 1, `<=2` — 1 или 2. Без суффикса нужно хотя бы 1. Условия проверяются независимо; один стек может удовлетворить ID и своему названию одновременно. Ник записывается один раз, только когда выполнены все условия.

Поддерживается показанное серверное окно `Player`. Проверяется весь верхний серверный контейнер после полного пакета содержимого; нижние слоты проверяющего игрока исключены. Автоматизация ничего не забирает и не перемещает. Пустое загруженное окно проходит без длительной паузы. `Ошибка: Игрок не найден.` и уход из TAB пропускают игрока. Если сервер молчит, запрос повторяется **тому же** игроку без лимита попыток: первый повтор через 1,5 с, затем интервал растёт до 5 с. После повторов выдерживается 2 с тишины для удаления повторных окон; новые окна продлевают этот период. Заголовок `Player` не содержит владельца: произвольно поздние ответы сервера невозможно безусловно сопоставить только по названию окна. `/6ubaafp stop` прерывает ожидание сразу. Отказ в правах останавливает сканирование с сохранением результата.

Результат — `6ubaafp-inv.txt` в корне **текущего** Minecraft-инстанса. Один гриф: ники через пробел. Full: только непустые строки `nick1 nick2 - grief #N`, по возрастанию 1–56. Файл сохраняется атомарно после каждого проверенного игрока и открывается штатным приложением ОС при завершении, `/stop`, отключении и обычном закрытии клиента. Независимый Java-процесс следит за Minecraft: после аварийного завершения игрового JVM он открывает уже сохранённый файл. Необходимы работающий Java и штатное приложение для TXT. Старый результат резервируется в `sixubaafp/<сессия>/previous-6ubaafp-inv.txt`; подробный журнал — рядом в `debug.log`, журнал помощника — `viewer-guard.log`.

## Обновления и оформление (1.3.0)

Esc немедленно останавливает `inv`/`invsee`, включая ожидание ответа и навигацию `full`; сохраняет и открывает уже полученный результат. На FP-проверку Esc не влияет.

`/6ubaafp update` показывает загруженную в память и найденную на GitHub версии, статус проверки/загрузки и автоперезапуск. Проверка выполняется при запуске клиента, каждом входе на сервер (включая одиночный мир) и по команде. Уже скачанное обновление не блокирует повторную проверку; SHA-256 проверенного JAR позволяет использовать его повторно без лишней загрузки.

`/6ubaafp update on` (по умолчанию): новая версия проверяется, запускается независимый помощник, отображается отсчёт 4 секунды, сохраняются результаты и завершается Minecraft. После выхода помощник делает резервную копию, устанавливает обновление и запускает Prism с `--dir` и `--launch` именно текущего инстанса. Работающий процесс Prism не требуется: учитываются путь оригинального `NewLaunch.jar`, установленные macOS-бандлы (включая названия с пробелами и суффиксами), Windows/portable-каталоги и PATH. При недоступном безопасном запуске игра не закрывается и показывает помощь.

`/6ubaafp update off`: Minecraft не перезапускается. Только после подтверждения READY от независимого помощника новый **обычный `.jar`** может быть скачан в `mods` рядом со старым. Работающий JAR не перезаписывается. После обычного выхода помощник сохраняет резервную копию старой версии и удаляет старый JAR, оставляя новую версию; лаунчер не запускается. На диске временно видны две версии, но в текущем клиенте работает только ранее загруженная. Не запускайте второй Minecraft в том же инстансе до завершения первого. Чужой или изменённый JAR не перезаписывается. Если безопасная загрузка/подготовка не удалась, при **каждом входе** показывается оформленная кликабельная ссылка `https://vk.ru/paveljaparov`. Настройка хранится в `.spidiboost-updates/settings.properties` и действует на единый обновлятор семейства SpidiBoost. В журнале Minecraft теперь явно видны loaded/GitHub/newer и готовность перезапуска, без токенов и аргументов аккаунта.

Важно: исправление обновлятора находится в 1.5.1. Уже работающий код 1.4.1 не меняется от публикации релиза: исправленный JAR требуется загрузить при очередном полном запуске Minecraft.

Собственная палитра медь → шампань → нефрит: анимированный префикс, мягкий градиент текста, центральные титры начала/окончания, actionbar и компактная адаптивная панель прогресса. По умолчанию панель находится по центру над actionbar. Открой чат и перетащи панель левой кнопкой мыши; положение сохраняется в `config/6ubaafp-hud.properties` текущего инстанса при отпускании кнопки или закрытии чата. При изменении GUI-масштаба панель ограничивается границами экрана. Строка результата в чате кликабельна. Чужие сообщения и цвета `/dupeip` не изменяются.

Изолированная нативная проверка: `./gradlew runVerification -PfpNative` (нужен локальный тестовый мир `build/runtime-verification/saves/SpidiCard-QA`). Fixture исключён из выпускаемого JAR и не подключается к пользовательскому серверу.
