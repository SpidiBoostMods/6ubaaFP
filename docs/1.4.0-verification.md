# 6ubaaFP 1.4.0

Fabric 1.21.4 / Java 21. Автор: SpidiBoost.

## Очередь FP

- Реестр запросов живёт на протяжении одного пользовательского `start` или всего `full`, а не одного грифа. Ключ — ник без учёта регистра. Следующий ручной запуск создаёт новый реестр.
- `/dupeip` и `/hist` отправляются не более одного раза на ник за запуск. Пересекающиеся группы и следующие грифы используют уже полученные группы/FP-совпадения. Повторы `/invsee` при лагах не затронуты.
- На сервере `Лимит` не совпадает с числом видимых банов. Завершённая причина, включая `[Горит]`, позволяет перейти дальше после обычного промежутка 5 мс. Не нужно ждать фиктивных записей и повторять `/hist` через 6 секунд.
- Каждый завершённый владелец остаётся доступен для поздних записей, в том числе после очистки чата. В конце очереди используется один период обработки хвоста до 100 мс, не задержка на каждого игрока. Произвольно поздние пакеты после завершения запуска не могут быть гарантированно учтены.
- Если ответ полностью отсутствует или обрывается внутри причины, остаётся тайм-аут 6 секунд; запрос не повторяется, проблема сохраняется в `unresolved.txt`. В `full` такой единичный сбой не запускает весь гриф повторно. Ошибка «Игрок не найден» пропускается сразу.
- Свой ник читается из текущего `client.player.getGameProfile()`, не из стартовой сессии лаунчера. Исключается как исходный игрок и как аккаунт из чужого `/dupeip`.
- Каждые 20 проверенных историй вызывается настоящий `ChatHud.clear(false)`. Очередь, реестр и результаты не хранятся в отображаемом чате и не удаляются.
- Красные FP-совпадения получают подпись `nick (На сервере: twin1, twin2)`: только жёлтые/золотые аккаунты той же группы, присутствующие в текущем TAB. Серые и другие красные аккаунты в подпись не попадают. Для выбора историй TAB-фильтр по-прежнему отключён.

Задержка 5 мс — минимальная пауза очереди после ответа, не обещание получить сетевой ответ за 5 мс. Команды отправляются последовательно на клиентском потоке, без пачки и блокирующего сна.

## Проверки

- JUnit: быстрые очереди, пересечения групп/регистра, кэш между грифами, новая ручная сессия, смена живого собственного аккаунта, красные подписи и уход из TAB, поздние записи, 45 историй с двумя очистками, 300 игроков со 100 записями на игрока, пустые истории, ошибки сервера и сохранение частичного результата. Сохраняются проверки инвентарей, маршрута 56 грифов и обновляющего помощника.
- Read-only replay локального реального журнала: 572 ответа, 155 пустых заголовков; все воспроизведённые завершённые истории проходят без повторного запроса. Сам журнал и реальные результаты не включены в репозиторий/архив выпуска.
- Изолированный нативный клиент: `./gradlew check build runVerification -PfpNative -PfpHistory`. Тестовый сервер отправляет настоящие стилизованные чат-пакеты, неверный лимит, `[Горит]`, пересекающиеся группы, красный аккаунт, позднюю FP-запись и собственный аккаунт. Проверяются уникальные команды, реальные очищенные сообщения, неизменившиеся совпадения, TXT и открытие редактора. Тестовый код не включён в выпускаемый JAR.
- Публичный release workflow проверяет Windows, macOS и Linux до загрузки артефактов. Он сверяет версии и формирует SHA-256 манифест для существующего автообновления.

Версия включает ранее локальные изменения 1.3.0: устойчивую очередь invsee, аварийное сохранение/открытие TXT, оформление, `/6ubaafp update on/off` и удаление алиаса `/6ubaa`. Исторический отчёт 1.3.0 описывает отдельные уже проведённые проверки инвентарей, UI и аварийного выхода JVM. SpidiCard в этот выпуск не входит. Пользовательская Prism-инстанция вручную не изменялась.
