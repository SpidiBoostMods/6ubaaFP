# spidiboost.6ubaaFP

Автор: **SpidiBoost**. Minecraft **1.21.4**, Fabric, Java 21, Fabric API.

Установка: `6ubaaFP-1.21.4-<версия>.jar` в `mods` нужного инстанса.

Автообновление проверяется при запуске клиента и подключении к серверу или локальному миру. Обновлятор отображает только установленные LittlePet, SpidiBan, 6ubaaFP и SpidiCard в одном окне; загружает подходящие релизы из SpidiBoostMods, сверяет SHA-256 и метаданные, сохраняет результаты и перезапускает игру один раз. JAR заменяются только после выхода игрового процесса. Резервные копии: `.spidiboost-updates/backups` текущего инстанса. Если надёжно воспроизвести запуск лаунчера нельзя, обновления устанавливаются после обычного выхода; запускать игру нужно через лаунчер.

GitHub недоступен — мод продолжает работать с установленной версией. Обновление одного мода не затрагивает конфигурации, миры или другие моды.

Релизы: https://github.com/SpidiBoostMods/6ubaaFP/releases/latest

Сборка: `./gradlew check build` (Java 21). Выпуск: тег `v<mod_version>`, автоматические проверки на Windows/macOS/Linux и публикация JAR, проекта с исходниками и manifest.

Версия **1.4.0**. Команды: `/6ubaafp start/full/stop/status/open/update`. Корень `/6ubaa` удалён.

Один запуск `start` или весь маршрут `full` отправляет `/hist` и `/dupeip` для каждого ника только один раз (без учёта регистра). Переход к следующей полной истории — через 5 мс после её ответа; `Лимит` не считается точным числом записей. Запоздалые записи сохраняют владельца. Пустой ответ не вызывает отдельной задержки; полностью отсутствующий ответ отмечается неполным после 6 секунд, без повторной отправки. Текущий игровой аккаунт исключается по живому профилю игрока, а не стартовой сессии лаунчера. Каждые 20 историй очищается только отображаемый чат; результаты и очередь остаются в памяти. Для красных аккаунтов с FP-банами добавляются присутствующие в TAB жёлтые твинк-аккаунты из той же группы: `nick (На сервере: twin1, twin2)`.
FP-проверка учитывает **все** жёлтые/золотые и красные/тёмно-красные никнеймы `/dupeip`, включая офлайн-аккаунты и отсутствующих в TAB. Проверки присутствия этих аккаунтов в TAB нет. Снимок TAB нужен только как исходный список владельцев для запросов `/dupeip`. Серые/другие цвета не проверяются. Результаты — `6ubaafp.txt` текущего инстанса.

## Поиск предметов в инвентарях

```text
/6ubaafp inv none minecraft:compass, Алмазный меч
/6ubaafp inv full minecraft:compass, Алмазный меч
/6ubaafp invsee minecraft:compass
/6ubaafp stop
```

`none` (или без указания режима) — один текущий гриф. `full` — по очереди все грифы 1–56, с прежней навигацией через компас. `inv` и `invsee` равнозначны.

Каждому игроку из снимка TAB отправляется `/invsee nick`. Никнеймы из `/dupeip` в этом режиме не используются. Запросы строго последовательные; минимальный интервал — 5 мс, фактическая скорость зависит от ответа сервера и кадров клиента. Ушедшие из TAB и явно недоступные игроки пропускаются. Требуются серверные права на `/invsee`.

Через запятую перечисляются альтернативы: ID предмета (`minecraft:compass`) либо точное отображаемое название (в том числе заданное на наковальне). Регистр, цвета и повторные пробелы игнорируются; поиск по подстроке не применяется. Название обычного непереименованного предмета зависит от языка клиента. Ник записывается один раз, если найден хотя бы один подходящий предмет.

Поддерживается показанное серверное окно `Player`. Проверяется весь верхний серверный контейнер после полного пакета содержимого; нижние слоты проверяющего игрока исключены. Автоматизация ничего не забирает и не перемещает. Пустое загруженное окно проходит без длительной паузы. `Ошибка: Игрок не найден.` и уход из TAB пропускают игрока. Если сервер молчит, запрос повторяется **тому же** игроку без лимита попыток: первый повтор через 1,5 с, затем интервал растёт до 5 с. После повторов выдерживается 2 с тишины для удаления повторных окон; новые окна продлевают этот период. Заголовок `Player` не содержит владельца: произвольно поздние ответы сервера невозможно безусловно сопоставить только по названию окна. `/6ubaafp stop` прерывает ожидание сразу. Отказ в правах останавливает сканирование с сохранением результата.

Результат — `6ubaafp-inv.txt` в корне **текущего** Minecraft-инстанса. Один гриф: ники через пробел. Full: только непустые строки `nick1 nick2 - grief #N`, по возрастанию 1–56. Файл сохраняется атомарно после каждого проверенного игрока и открывается штатным приложением ОС при завершении, `/stop`, отключении и обычном закрытии клиента. Независимый Java-процесс следит за Minecraft: после аварийного завершения игрового JVM он открывает уже сохранённый файл. Необходимы работающий Java и штатное приложение для TXT. Старый результат резервируется в `sixubaafp/<сессия>/previous-6ubaafp-inv.txt`; подробный журнал — рядом в `debug.log`, журнал помощника — `viewer-guard.log`.

## Обновления и оформление (1.3.0)

`/6ubaafp update` показывает установленную и найденную на GitHub версии, статус проверки/загрузки и автоперезапуск. `/6ubaafp update on|off` меняет **только перезапуск**; по умолчанию `on`. При `off` проверка, загрузка и проверка SHA-256 продолжаются, но Minecraft не закрывается автоматически. Подготовленные JAR безопасно заменяются в `mods` после выхода игрового JVM. Общая настройка этого инстанса хранится в `.spidiboost-updates/settings.properties` и действует на единый обновлятор семейства SpidiBoost.

Собственная палитра медь → шампань → нефрит: анимированный префикс, мягкий градиент текста, центральные титры начала/окончания, actionbar и компактная адаптивная панель прогресса слева сверху (не перекрывает чат и серверный scoreboard). Строка результата в чате кликабельна. Чужие сообщения и цвета `/dupeip` не изменяются.

Изолированная нативная проверка: `./gradlew runVerification -PfpNative` (нужен локальный тестовый мир `build/runtime-verification/saves/SpidiCard-QA`). Fixture исключён из выпускаемого JAR и не подключается к пользовательскому серверу.
