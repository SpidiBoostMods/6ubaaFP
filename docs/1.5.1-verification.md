# 6ubaaFP 1.5.1 — updater verification

Fabric / Minecraft 1.21.4 / Java 21; author SpidiBoost. No manual changes to the user's Prism instance or recording.

## Behavior

- Client startup, every server/singleplayer JOIN and the update command check the loaded version against the public manifest. An already prepared update does not suppress another manifest request. A verified matching JAR is reused.
- Native Prism launch is recovered from NewLaunch.jar's original installation, existing launcher ancestors, macOS app bundles, Windows/portable locations or PATH. The CLI carries the current instance ID and application root as separate arguments; it does not replay Prism EntryPoint's expired IPC.
- On: READY exit helper, four-second native countdown (with update-off button), result preservation, game exit, backed-up installation, native launcher/instance request.
- Off: READY exit helper before publishing a new ordinary JAR beside the still-running old JAR. The live JAR is never rewritten. After exit the old version is backed up and removed, without a launcher restart. Only updater-owned pending files are accepted; modified or foreign destination JARs are preserved. Rollback removes owned uncommitted downloads to avoid duplicate mods after a failed transaction.
- Failure notices use native styled Text with a clickable exact https://vk.ru/paveljaparov URL. Separate entries/checks repeat the notice; no once-per-process flag suppresses it.
- A preferred prelaunch reservation prevents an older relocated updater from taking control, regardless of client entrypoint order. Protocol remains compatible with older family copies.
