# 1.2.0 verification

Target: Minecraft 1.21.4, Fabric, Java 21. Author: SpidiBoost.

Local verification:

- `./gradlew check build -PfpSmoke runClient --no-daemon`
- JUnit covers serial invsee requests, 1,000 players, exact renamed/display names and registry IDs, comma alternatives, blank/full inventory packets, delayed updates, sync IDs, wrong/replaced windows, unavailable/leaving players, file failure, stop/disconnect and partial checkpoints, both grief pages and all 56 slot mappings.
- The pure Java state machine uses a minimum 5 ms inter-request gap. This is not a promise of 200 server replies per second; requests are serialized and wait for content.
- FP regression: offline yellow/red/dark-red dupeip accounts are checked without reading TAB while dispatching their histories. Gray accounts are not queried. The initial owner list for dupeip is still the current grief's TAB snapshot.
- Isolated native client loads the real mixins, parses all 12 inventory command forms and existing aliases, tests native red Text and offline ban history, native ItemStack registry names and custom-name data components, applies InventoryS2CPacket contents to a real 9x4 container handler, excludes the viewer's 36 lower slots, verifies empty/populated inventory scan outcomes, renders the native `Player` container, and saves a screenshot.
- The isolated run uses only `build/fp-smoke`, does not connect to a public server or change a live instance. The native file opener is exercised there.
- The updater preservation hook is present; relocated shared updater sources and protocol are unchanged. Existing updater transaction/election/artifact tests remain enabled.

Release workflow gates publication on Java 21 checks for Windows, macOS and Linux, then packages the version-consistent JAR, source project and SHA-256 manifest. Public downloaded artifact identity/hash must be verified after publication.

Limits: the real public server's permissions, RTT and `/invsee` behavior have not been exercised by this isolated verification. The implementation uses the supplied `Player` GUI contract. Because the title contains no nickname, a missing/incomplete window times out and stops with partial results, rather than attributing a late response to the next player. Force-killing the process retains already checkpointed output but cannot open an editor after death.
