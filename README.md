# spidiboost.6ubaaFP

1.9.1: меню корректно открывается после Enter в чате. AutoRG понимает «Цель не забанена!» без ника и не повторяет такой запрос. `__global__` и `__default__` всегда пропускаются; `(none)` и кнопки управления регионом не считаются игроками. Снимок сохраняется как PNG по размеру текста региона, без прозрачных полей. Windows: сначала «Фотографии», при недоступности — приложение по умолчанию. Ассоциации файлов не меняются.

1.9.0: журнал твоих подтверждённых банов по версиям и грифам, проверка разбаненных и AutoRG.

`/6ubaafp menu` — оконное меню: Инвентарь, Баланс, Баны, Разбаны, FP-поиск слева друг под другом, ниже — AutoRG. Перетаскивание за верхнюю панель, изменение размера за нижний правый угол; последний раздел и положение сохраняются. Поиск работает в разделе или везде. Двойной клик выделяет целый ник, включая `_`; доступны Ctrl/Cmd+C, Ctrl/Cmd+A и меню по правой кнопке.

Наведи на ник в «Баны» или «Разбаны», чтобы увидеть причину, гриф и время последнего бана на нём. Время — местное, по часовому поясу твоей системы. Подсказки сохраняются при общем поиске.

`/6ubaafp bans` — текстовик банов. `/6ubaafp start unbans` — поиск игроков из журнала текущего грифа в TAB, затем открытие раздела «Разбаны». `/6ubaafp unbans` — текстовик результата. Один ник может находиться в журнале нескольких грифов. Неподтверждённые команды и баны других администраторов не записываются.

`/6ubaafp autorg on/off` — также тумблер в меню. После `/rg i` мод проверяет владельцев и участников региона. Если забанено ≥30%, открывает снимок ответа региона и копирует `.хата x y z гриф-версия`. Если регионов несколько, перебирает их до первого подходящего. По умолчанию выключен. Для всех этих функций нужна подписка 6ubaaFP.

С 1.8.0 подписки SpidiCard и 6ubaaFP показываются в одном окне: отдельная карточка для каждого установленного мода, статус доступа и оставшийся срок. Ответы обновляются прямо в окне, без второго меню следом. Подписки остаются независимыми. Если установлен один мод, отображается только его карточка.

Minecraft 1.21.4 · Fabric · Java 21 · Fabric API. Главный владелец: **SpidiBoost**.

[Скачать последнюю версию](https://github.com/SpidiBoostMods/6ubaaFP/releases/latest).

С 1.6.0 требуется отдельная подписка 6ubaaFP: trial на 7 суток с выдачи, до даты или бессрочная. Подписка SpidiCard не предоставляет доступ к 6ubaaFP, и наоборот. С 1.8.1 код устройства, имя пользователя ОС и имя компьютера автоматически передаются в закрытый реестр SpidiBoost при запуске Minecraft; нажимать кнопки подписки или копирования кода не требуется. Изменённые системные имена обновляются в той же записи HWID без дублей. Исходный идентификатор машины не передаётся.

Доступ проверяется при запуске, каждом входе на сервер и раз в 30 секунд одним фоновым исполнителем. При недоступности Cloudflare используется независимый резерв Google. Выдача, продление и отзыв показывают меню после ближайшей проверки; истечение срока определяется локально. Остановка, потеря соединения и истечение сохраняют найденные результаты.

`/6ubaafp sub` — тип, срок или отсутствие подписки только в чат, без title и браузера. `/6ubaafp update`, `/6ubaafp update on`, `/6ubaafp update off` работают без подписки. Оба режима показывают единое меню установленных модов SpidiBoost; on/off меняют автоперезапуск, скачивание остаётся включённым. Общих `/sub` и `/update` у мода нет.

Сохранены `/6ubaafp start`, `full`, `stop`, `status`, `open`, `inv` и `invsee`. Истории FP/Funpay/Playerok проверяются через TAB, `/dupeip` и `/hist`; инвентари — через `/invsee`. Поиск инвентарей поддерживает название предмета или registry ID, количество `obsidian(6)`, несколько условий через запятую и маршруты, например `/6ubaafp inv full 3-5, 8-12 minecraft:compass`. HUD перетаскивается из чата, положение сохраняется. Результаты и предыдущие запуски сохраняются в текущем инстансе.

С 1.6.1 связки `FP_RW` и `FP RW` не считаются FP-причиной в любом регистре. Обычный `FP` учитывается. Если в той же причине есть отдельный `FP`, `Funpay` или `Playerok`, она по-прежнему подходит.

С 1.8.1 `/6ubaafp start bal` проверяет `/bal` игроков текущего TAB, исключая собственный ник без учёта регистра. `/6ubaafp bal 3000000` задаёт минимальный баланс (по умолчанию 3 миллиона, граница включена), `/6ubaafp delay 100` — интервал между запросами в миллисекундах. Проверки идут по одной, без пучков; настройки сохраняются. Прогресс отображается в перетаскиваемой панели. Ники записываются через пробел в `6ubaafp-bal.txt` текущей папки игры, файл открывается после завершения. `/6ubaafp stop`, Esc или потеря соединения сохраняют частичный результат. Ответы читаются из серверных пакетов до разделения и скрытия чатов; пропавший игрок пропускается, запрос без ответа повторяется до трёх попыток.

Обновлятор проверяет SHA-256 и метаданные, сохраняет результаты и резервные копии. Работающий JAR заменяется после выхода; при невозможности безопасно воспроизвести запуск лаунчера требуется обычный повторный запуск.

Подписанные ответы привязаны к назначению sixubaafp, устройству, случайному запросу, сроку и официальной контрольной сумме JAR. Исходники и карты обфускации хранятся в закрытом [SixubaaFPSource](https://github.com/SpidiBoostMods/SixubaaFPSource). Новые релизы содержат только защищённый JAR и manifest. Старые выпуски до 1.6.0 не содержат этой системы; абсолютной защиты Java-клиента от модификации нет.
