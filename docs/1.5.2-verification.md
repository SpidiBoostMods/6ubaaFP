# 6ubaaFP 1.5.2 — quiet updater verification

Fabric / Minecraft 1.21.4 / Java 21; author SpidiBoost. No manual changes to the user's Prism instance, Minecraft process or recording.

## Change boundaries

- Automatic startup and JOIN checks no longer open checking/completed/error windows or emit current-version/network-failure chat messages. Only a verified, actionable update retains the installation/restart UI.
- Failed checks schedule discovery-only retries: 30, 60, 120, 240, then 300 seconds, capped at 300. Success resets backoff and ends retries. A new entry still makes a fresh check immediately, without waiting for the timer.
- Discovery only requests the manifest. It cannot download an artifact, create an exit helper, publish a JAR to mods or call restart behavior. A release discovered by retry waits for a later startup/JOIN activation check; an explicit on/off preference action remains user-initiated.
- Serialized/coalesced checks retain a queued JOIN's activation authority when a discovery check is running. A timer never inherits authority from a failed earlier entry.
- `/6ubaafp update` explicitly requests status and can report GitHub's unavailability. on/off no longer automatically invokes this verbose status command. A healthy current-version status omits the redundant second line.
- An actual prepared update that cannot be safely installed or launched retains actionable support. A mere GitHub/network failure does not show support.
- Shared protocol, detached installation transaction and closed-Prism discovery are unchanged. Canonical shared template and this mod's generated copy match. Other project distributions are not published or installed by this release.

## Verification contract

- Local build and JUnit suite cover backoff/reset/cap, discovery after a failed activation, concurrent election and queued activation priority, current/older/newer manifests, empty/malformed/wrong-Minecraft manifests, silent recovery and rejection of cached-release fallback on a failed manifest request. Existing scanner, inventory, route, HUD, backup/rollback and detached helper tests remain in the suite.
- Isolated native client probe directly exercises offline entry, failing retry, healthy current-version entry/discovery and newer-version discovery against actual ChatHud/current screen. It asserts zero new messages/screens, no created QA directory, no artifact HTTP request and no installation plan/helper. It also rechecks existing real-client off publication, real countdown and process exit, followed by detached agent installation and a controlled launcher substitute.
- Timer delays and queue interleavings are deterministic unit tests, not a claim of having observed a multi-minute GitHub outage live. Native HTTP responses are controlled fixtures; the user's server, mods and live launcher session are not touched. Actual authenticated Prism-to-Minecraft relaunch remains outside this fixture.
- GitHub release publication is gated on Windows/macOS/Linux checks. After publication, the anonymous latest manifest must match the public JAR's metadata and SHA-256; production class bytes are compared with the locally verified artifact.
